| ACT1 | 🐞 **BUG — a raced duplicate `Attributes["phone"]` on `CreateActor` is misclassified as `ErrDuplicateID` and surfaces to an HTTP caller as `500 "internal error"` instead of the clean `400` a sequential duplicate gets.** `checkUniqueAttributes`'s Go-level precheck is documented as a pre-check only, backstopped by `gormstore.syncUniqueAttributeIndexes`'s DB-level partial unique index for the case where two concurrent `CreateActor` calls both race past the precheck — driven directly with a deterministic forced interleave (`db.Callback().Query().After("gorm:query")` barrier holding both goroutines' precheck reads until both have actually read back "zero matching rows", then releasing both to their own transaction/insert): the DB-level index *does* correctly stop the second insert (`UNIQUE constraint failed: index 'test_actors_attr_phone_uniq'`), so no duplicate row is ever written — but `actor_impl.go`'s `classifyDuplicateID` treats **any** unique-constraint violation on the actors table (Postgres SQLSTATE `23505`, or sqlite's `"UNIQUE constraint failed"` substring match) as a primary-key collision and returns `ErrDuplicateID`, even when the violated index is the phone-attribute index, not the row's `id`. Confirmed via the real `routes.ActorRoutes` mux + `httptest.Server` + `http.Client`: the losing concurrent `POST /actors` request gets `500 {"error":"internal error"}` — because `routes/actor.go`'s `actorStatusFor` has no `case` for `ErrDuplicateID` at all and falls through to its default 500 arm — where the *identical* duplicate-phone body sent sequentially (caught by the Go-level precheck, which correctly returns `ErrDuplicateAttribute`) gets a clean `400`. So the DB-level backstop the doc comments describe as existing specifically to catch this race does catch it, but produces a worse-quality error (wrong sentinel, opaque 500) than the case it exists to guard against would get without the backstop at all. **Fix location**: `actor_impl.go:57-70`'s `classifyDuplicateID` (distinguish the violated index/constraint name rather than treating every unique violation as a PK collision — e.g. match on the `test_actors_attr_phone_uniq`/`_attr_<name>_uniq` naming `gormstore.syncUniqueAttributeIndexes` gives each attribute index, returning `ErrDuplicateAttribute` for those and `ErrDuplicateID` only for the real primary-key constraint), and/or `routes/actor.go:18-28`'s `actorStatusFor` (map `ErrDuplicateID` to a real 4xx instead of leaving it to fall through to 500).
